# Graph specification: Melinda's 2×2×2×2, CTM-free-rotations-v1

## 1. Scope and metric

This defines a reproducible mathematical search problem on the states of
Melinda Green's physical 2×2×2×2. It proposes **cell-turn metric with free proper
rigid rotations**. It does not claim to reproduce a competition's unpublished
rules, physical action count, or speedsolving score.

The physical sources distinguish cell turns from whole-puzzle reorientations.
The two exposed cubic cells admit arbitrary proper cube rotations. Simple
rotations together with completed gyros allow changing which cells are exposed.
Thus, under the explicit convention that these reorientations cost zero, a
turn of any cell may be realized by exposing it, turning it, and reorienting
back. The canonical long-cell half turns are already included as cell turns.

There are 23 nonidentity proper rotations of a cube. Each costs one here:
6 quarter turns, 3 face-axis half turns, 6 edge-axis half turns and 8 third turns.
The convention extends the source's arbitrary-half juxtaposition to every
cell through free reorientation. This is a modeling choice for community review,
not a new assertion about how physical records are scored.

No intermediate state of a gyro is introduced as a puzzle vertex. Interrupting
a gyro and treating its intermediate manipulations as ordinary legal moves is
outside this definition. Counting those actions requires a different model.

## 2. Coordinates and sticker IDs

Use axes `x,y,z,w`, indexed 0,1,2,3. Corner positions are

\[
V=\{-1,+1\}^4.
\]

A sticker slot is `(v,a)` for `v in V` and `a in {0,1,2,3}`. Its outward
normal is `v[a] e_a`. There are 16 × 4 = 64 slots. Order corners
lexicographically with -1 before +1; order sticker axes x,y,z,w within each
corner. Equivalently, for `b_i=(v_i+1)/2`,

\[
\operatorname{id}(v,a)=4(8b_0+4b_1+2b_2+b_3)+a.
\]

Each sticker receives its solved slot ID. A state `s[j]` gives the sticker
currently occupying slot `j`. The solved state is `(0,1,...,63)`.
The solved color of `(v,a)` is `(a,v[a])`; `slots` in the JSON gives this mapping.
The unique IDs track orientation and piece identity, not extra painted markings:
each corner's four-color set is unique, and its four stickers have distinct colors.

The four reference stickers 60,61,62,63 form the `(+,+,+,+)` corner. In the
default graph they remain in their solved slots. Keeping the four constant
entries makes the correspondence with the full 64-slot representation explicit.

## 3. Geometric moves

For a cell `(a,sigma)` take all corners with `v[a]=sigma`. Select a 3×3 signed
permutation matrix of determinant +1 on the other three axes; extend it to a
4×4 matrix `R` that fixes `e_a`. Unless `R=I`, this is a move:

\[
(v,n)\mapsto
\begin{cases}
(Rv,Rn),&v_a=\sigma,\\
(v,n),&v_a\ne\sigma.
\end{cases}
\]

Here `n=v[b] e_b` is the outward sticker normal. Only proper rotations are
allowed; reflections would create an invalid physical model.

The full framed set has `8 × 23 = 184` distinct, nonidentity generators. The
default fixed-corner set takes only the four negative cells `(a,-1)`, leaving
`4 × 23 = 92`. Both sets are inverse-closed. Every generator has cost 1.

Generator names specify the source cell and images of its tangent basis axes
in increasing source-axis order. `n` means -1, `p` means +1. For example:

`xn_+y_-w_+z`: act on `x=-1`; map `e_y -> e_y`, `e_z -> -e_w`, `e_w -> e_z`.

Its geometric coordinate action is
`(x,y,z,w) -> (x,y,w,-z)` in that cell. These are unambiguous mathematical
labels, **not** a claim of compatibility with a particular simulator's `R/L/I/O`
notation. Translating solutions into physical hand instructions is separate.

## 4. Permutation direction and graph

The geometry supplies a source-to-destination permutation `T`. The exported
array is its inverse `p=T^-1`, because CayleyPy applies permutations as gathers:

\[
s'_j=s_{p_j}.
\]

Applying named moves left to right means repeatedly applying this formula.
Inverse names are given explicitly in `inverse_moves`.

Let `S` be the 92 default gather permutations and `H=<S>`. The vertex set is
`H`, represented by the states reachable from identity; the edge set joins `s`
and `apply(s,p)` for every `p in S`. This defines a finite, connected, simple,
undirected 92-regular Cayley graph. It does not assert that every permutation
of 64 entries is a reachable state. Full enumeration is never required.

Solving a case means finding a word in `S` that returns its state to identity.
Its length is an upper bound on the shortest-path distance. The graph diameter
and optimal lengths of the supplied examples are not claimed to be known.

## 5. Why fixing a corner is valid

Let `G` be generated by all 184 framed cell turns. Let `K` be the proper rigid
rotation group of the tesseract, the determinant-positive signed permutation
matrices in dimension 4. It has `2^3 × 4! = 192` elements.

An oriented reference corner determines a unique rigid coordinate frame:
there are 16 possible positions and 12 handedness-preserving sticker
orientations, hence 192 frames. Every reachable state can therefore be
uniquely normalized by a rigid rotation so the reference corner returns to
its solved position and orientation. `normalize` implements this operation.

Consider a cell turn `R` while the reference corner is fixed:

1. If the cell does not contain the reference corner, it is one of the 92
   default moves and no normalization is needed.
2. If it contains the reference corner, apply that turn and then the rigid
   rotation `R^-1` to the entire puzzle. The turned half returns to its prior
   position; the opposite half has undergone the inverse cell turn. This is
   again one of the 92 default moves.

Conjugation by a proper rigid rotation preserves the all-cell generator set.
Consequently every framed turn, with any free reorientations, corresponds to
one fixed-corner turn; conversely every fixed-corner turn is a permitted cell
turn. Normalizing therefore preserves shortest-path distances in the chosen
metric. The two opposite turns paired above give the same normalized neighbor,
which explains the reduction from 184 to 92.

This is a graph on rotation classes, realized as the Cayley graph of the
reference-corner stabilizer. **It is not a claim that `K` is normal in `G` or
that the algebraic quotient group `G/K` exists.**

## 6. State counts and independent checks

The source publishes the rotation-reduced count

\[
|H|=\frac{16!\,12^{16}}{6\cdot192}
=3\,357\,894\,533\,384\,932\,272\,635\,904\,000.
\]

The framed graph has `192 |H| = 16! 12^16 / 6` vertices. Fixing one reference
corner accounts for 16 × 12 = 192; the factor 6 in the framed count includes
the even corner-permutation and global orientation constraints. We define the
state space by generators, so no incomplete list of invariants is used as a
reachability test.

`check_group_order.py` uses SymPy's exact Schreier-Sims calculation to obtain
both orders from the exported construction. It also checks that the induced
corner permutation groups have orders `15!/2` and `16!/2`. These tests would
detect a generator construction that produces only a smaller corner subgroup.
Matching group orders alone is not the physical correspondence argument;
the geometric cell construction and metric explanation above supply that.

`test_graph.py` checks inverse closure, corner integrity, parity, generator
orders, a named coordinate action, all 192 rigid orientations of sample states,
and equality of normalized 184-move neighborhoods with the 92-move neighborhoods.
It also tests reproducible exports and rejects malformed/incomplete/unsolved
submissions. `normalize` checks the reference corner, **not all reachability
constraints**; generate test positions by legal random walks.

## 7. Portable data and example scoring

The default `data/puzzle_info.json` is schema version 1 of this repository.
It exports solved state, named gather arrays, inverse names, unit cost, indexing
and state count as a decimal string (to avoid JSON integer precision loss).
`as_cayleypy()` maps it to `CayleyGraphDef.create`.

`data/framed_puzzle_info.json` is a separate auxiliary graph with a fixed
coordinate frame. Its identity-only distances are not automatically the
free-rotation distances. Do not mix its 184 moves with the default benchmark.

The 24 public examples are generated from seed 20261101, eight at each word
length 10, 30 and 60. Consecutive turns of the same cell are excluded. The
inverse construction words provide valid baseline solutions totaling 800.
The sampling is deliberately simple and non-uniform; optimality, uniform mixing
and representative difficulty are not asserted. This is an initial public
benchmark for experimentation, not a hidden competition test set.

The verifier requires every example exactly once, known move names and exact
return to identity. It returns the sum of move counts, with lower better. No
target length is imposed on participants. A separately organized competition
may choose its own instances and scoring after accepting a metric.
